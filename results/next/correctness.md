# 正しさの確認（枠の共有 `LLAMA_MOE_CACHE_SHARE`）

計測日 2026-11-22。`scripts/check_shared.py`、生の値は `correctness.csv`、ログと応答は `runs/check_shared/`。

条件: `-ngl 99 -cmoe -ub 32 --moe-cache-mib 7296 -lm none`、温度 0、3 つのプロンプト（英語のコード、日本語、英語の説明）、各 320 トークン。

| 確認したこと | 結果 |
|---|---|
| 共有なしのとき、前と同じ動きか | ログの host experts は 28188.00 MiB、トレースの層は 44+4。前回と同じ |
| 共有ありのとき、ログの host experts | 15066.00 MiB（実際のエキスパートの大きさ） |
| 共有ありのトレース | 層は 20+4。上流のチューナーの読み取りでそのまま読める |

| 温度 0 の出力（CPU 分担 0.95） | 一致しない。ただし下の理由で、共有のせいではない |
| サーバーのヒット率と、そのトレースの再生 | 分担 0: 80.48% / 80.48%（なし）、94.00% / 94.00%（あり）。分担 0.95: 70.10% / 69.68%、86.57% / 86.21% |

## CPU 分担 0.95 で出力が一致しない理由

CPU 分担を使うと、ミスの一部を CPU が計算する。CPU と GPU では浮動小数点の計算結果がわずかに違うので、
どのエキスパートが CPU に回るかで、僅差のトークンの選択が変わる。

これは共有と関係なく起きる。共有なし同士でも、分担 0 と分担 0.95 の出力は 3 つとも途中で食い違った
（206 / 295 / 435 文字目）。共有ありの分担 0.95 は、分担 0 の出力と 1 つ目が完全に一致し、残りは 338 / 870 文字目で食い違った。

共有そのものの正しさは、CPU に回る分が無い分担 0 で見るのが適切で、そこでは完全に一致した。
