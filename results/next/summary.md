## 3. 出力が壊れる構成が見つかった（重要）

ubatch 64 の構成は、生成 48 トークン/秒・ヒット率 99% と出たが、出力は全部「?」だった。壊れた出力は同じ記号の繰り返しなので、
ルーティングも繰り返し、キャッシュがよく当たる。速さとヒット率だけ見ると最良に見える。

- 切り分け（`garbage_diag.csv`、`garbage_diag2.csv`）: ホストに置いたエキスパートを、大きいバッチのたびに GPU へコピーして計算する経路を通ると壊れる。
  キャッシュなしの `-cmoe` は ubatch 32 / 33 / 64 / 512 のどれでも壊れた。`-ncmoe 13` でも ubatch 64 / 512 で壊れた。
  同じ `-cmoe -ub 64` でも、プロンプトが 25 トークンなら正常だった。
- キャッシュを使う ubatch 32 以下の構成は、文脈 4096 / 8192 / 32768、温度 0 / 既定のどれでも正常だった。
- 改造を入れない本家でも起きる。原因は調べていない。本家の新しいコミットで直っているかも確かめていない。
- **1 回めへの影響**: 1 回めの B2（`-ngl 99 -cmoe`、ubatch 512。生成 11.82、プロンプト処理 303.1）も出力が「?」だった。
  1 回めでは、出力の中身を全構成では確かめていなかった。B2-ub16（生成 12.00、出力は正常）に差し替える訂正を用意した。
  ほかの構成（B1、S1、S2、サイズ振り、用途別）は、保存した出力を点検して正常と確かめた。「2.4 倍」は 28.31 / 12.00 = 2.36 で変わらない。
- 以後、`summarize_next.py` は構成ごとに出力の点検結果（`output_ok` 列）を付ける。
